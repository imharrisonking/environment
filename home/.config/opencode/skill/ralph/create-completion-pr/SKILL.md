# Skill: Create Completion PR

You are the PR Creation Specialist. Your goal is to create comprehensive Pull Requests after Ralph completes all tasks in a phase.

## Instructions

When invoked, perform these steps in order:

### 1. Read Context Files

Read these files to gather context:

**A. specs/prd.json**
- Extract: `branchName`, `project`, `description`, and all completed user stories
- Count: Total tasks, completed tasks (where `passes: true`)

**B. specs/plan/progress.txt**
- Extract: All "Completed Tasks", "Blocked Tasks", "Failed Tasks"
- Look for: "Key Patterns", "Gotchas", "Lessons Learned"
- Note: Any technical decisions or architectural choices

**C. specs/plan/XX-name.md**
- Extract: Phase goals, proposed changes, user stories, testing plan
- Parse phase name and number from the filename (e.g., "01-setup" → Phase 01)

**D. docs/STATUS.md**
- Locate the current phase in the Phase Summary table
- Check current status (should be "In Progress" or "⏳ In Progress")

### 2. Update docs/STATUS.md

Update the STATUS.md file:

**A. Mark Phase as Complete:**
- Find the current phase in the Phase Summary table
- Change status from "In Progress" to "✅ Complete"

**B. Add Completion Summary:**
- Add new section: `## Phase [XX] Completion Summary`
- Include:
  - Brief overview (1-2 sentences)
  - Key features delivered (bulleted list)
  - Any notable achievements

**C. Update "Next Up" Section:**
- Point to the next phase from the roadmap
- Remove completed phase from "Current Phase" section

### 3. Synthesize PR Description

Create a comprehensive PR body using this template:

```markdown
## Phase [XX]: [Title from prd.json description]

### Executive Summary
[2-3 sentences synthesizing what this phase achieved, based on the phase spec and completed tasks]

### Completed Tasks
- ✅ **US-001**: [Title] - [Brief outcome from acceptance criteria or progress.txt]
- ✅ **US-002**: [Title] - [Brief outcome]
- ✅ **US-003**: [Title] - [Brief outcome]
[...list all completed tasks...]

### Lessons Learned

**Key Patterns Discovered:**
[Extract from progress.txt - any recurring patterns, conventions discovered]

**Gotchas & Important Notes:**
[Extract from progress.txt - any important warnings, edge cases, or tricky aspects]

**Technical Decisions:**
[Any architectural decisions made during implementation, e.g., library choices, data structures]

### Testing
- All tasks completed: [N/N] tasks passing
- Verification: [Manual/automated testing performed - details from progress.txt]

### Files Changed
[Generate via bash command: `git diff --name-only production... | head -20`]

### References
- Phase Spec: `specs/plan/XX-name.md`
- Updated: `docs/STATUS.md` with completion summary
- Implementation: All commits in this branch

---

_Automatically generated by Ralph autonomous agent loop_
```

### 4. Push Branch to Remote

Ensure the feature branch is pushed to origin:

```bash
BRANCH_NAME=$(jq -r '.branchName' specs/prd.json)

# Check if branch is already pushed
if ! git rev-parse --verify "origin/$BRANCH_NAME" >/dev/null 2>&1; then
  echo "Pushing branch to remote: $BRANCH_NAME"
  git push -u origin "$BRANCH_NAME"
else
  echo "Branch already pushed to remote"
fi
```

### 5. Create PR to `production`

Create Pull Request to the `production` branch:

**A. Check if PR already exists:**
```bash
BRANCH_NAME=$(jq -r '.branchName' specs/prd.json)
PR_COUNT=$(gh pr list --head "$BRANCH_NAME" --base production --json number -q '. | length')

if [ "$PR_COUNT" -eq 0 ]; then
  # PR doesn't exist, create it
else
  echo "PR to production already exists - skipping"
fi
```

**B. Create PR if needed:**
```bash
PRD_TITLE=$(jq -r '.description' specs/prd.json)
PRD_BODY="[The synthesized PR body from step 3]"

gh pr create \
  --base production \
  --head "$BRANCH_NAME" \
  --title "$PRD_TITLE" \
  --body "$PRD_BODY"

echo "Created PR to production"
```

### 6. Create PR to `dev`

Create Pull Request to the `dev` branch:

**A. Check if `dev` branch exists:**
```bash
if git rev-parse --verify origin/dev >/dev/null 2>&1; then
  echo "dev branch exists - will create PR"
else
  echo "Warning: dev branch does not exist - skipping PR to dev"
fi
```

**B. Check if PR already exists:**
```bash
BRANCH_NAME=$(jq -r '.branchName' specs/prd.json)
PR_COUNT=$(gh pr list --head "$BRANCH_NAME" --base dev --json number -q '. | length')

if [ "$PR_COUNT" -eq 0 ]; then
  # PR doesn't exist, create it
else
  echo "PR to dev already exists - skipping"
fi
```

**C. Create PR if needed:**
```bash
PRD_TITLE=$(jq -r '.description' specs/prd.json)
PRD_BODY="[The synthesized PR body from step 3]"

gh pr create \
  --base dev \
  --head "$BRANCH_NAME" \
  --title "$PRD_TITLE" \
  --body "$PRD_BODY"

echo "Created PR to dev"
```

### 7. Cleanup Files

Remove the task tracking files (no archiving):

```bash
rm -f specs/prd.json
rm -f specs/plan/progress.txt
echo "Cleaned up specs/prd.json and specs/plan/progress.txt"
```

### 8. Emit Completion Signal

After all steps complete, output:

```
<promise>COMPLETE</promise>
```

## Error Handling

**If `gh` CLI is not installed:**
- Output error message: "GitHub CLI (gh) not found. Please install and authenticate."
- Emit failure signal, do not create PRs

**If git push fails:**
- Output error message with details
- Do not continue with PR creation
- Exit with failure

**If STATUS.md cannot be updated:**
- Log warning but continue with PR creation
- Note in PR description that STATUS.md was not updated

**If dev branch doesn't exist:**
- Log warning
- Continue with production PR only
- Do not fail

**If PR already exists:**
- Log info message
- Skip creation, continue with other targets

## Important Notes

1. **PR Body Quality:**
   - Must be human-readable and comprehensive
   - Include actual content from progress.txt (not just references)
   - Synthesize, don't copy-paste raw content

2. **STATUS.md Updates:**
   - Be precise with markdown formatting
   - Ensure phase status table is correctly updated
   - Add completion summary before the next phase section

3. **Branch Management:**
   - Use exact branchName from PRD (no modifications)
   - Handle branch naming case-sensitively

4. **Cleanup:**
   - Only remove prd.json and progress.txt
   - Do NOT archive files
   - Do NOT remove phase specs or STATUS.md

## Output

After successful completion, output a summary:

```
✅ Created PR to production: https://github.com/[repo]/pull/[number]
✅ Created PR to dev: https://github.com/[repo]/pull/[number]
✅ Updated docs/STATUS.md with Phase [XX] completion
✅ Cleaned up task tracking files
```

Then emit: `<promise>COMPLETE</promise>`
